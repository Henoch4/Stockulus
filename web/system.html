Architecture

Four pieces. Each one can only do its own job.

The signal engine decides what looks attractive. It has no power to override the risk gate. The risk gate can block a trade; it can't write to the chain. The audit trail can refuse to log; it can't place a trade. Splitting the jobs this way is what makes the limits actually mean something.

01 — Signal engine

Reads the gap, not the news.

Stockulus prices the "cost of carry" for each tokenized stock — the combined effect of the risk-free rate, the dividend yield it's missing by holding the token instead of the real share, and the cost of borrowing. When the tokenized price sits far enough above (or below) that fair value, and stays there, that's a tradeable signal in either direction.

02 — Risk gate

Can only get stricter, never looser.

Every proposed trade passes through a gate that isn't part of the signal logic — it can't be reasoned around. Limits can be tightened by an operator, but never loosened past their last approved value, and a kill switch halts everything immediately if daily loss or trade-count limits are hit.

03 — Audit trail

On-chain before, not after.

Every approved decision is written to a Solana program before Stockulus executes the trade — asset, size, confidence, and a hash of the reasoning behind it. The record is immutable once written, and the same program tracks daily loss and trade counts independently of the off-chain agent, so a crash or restart can't quietly reset the day's limits.

04 — Vault

Deposits, priced fairly, every time.

Deposits go into a vault that issues shares representing a proportional claim — priced off the vault's attested holdings, not a number the agent can invent on the spot. NAV updates are capped in how far they can move per attestation and rate-limited, so a single bad or malicious update can't reprice everyone else's shares.

Share pricingProportional to attested holdings
NAV update capBounded delta per attestation
Update frequencyTimelocked between attestations
WithdrawalsBlocked mid-trade, open otherwise

This is the one component still being hardened before real deposits — see Docs for current status.

Where the money actually moves: through Meteora's bonding-curve pools.

Each tokenized stock has its own liquidity pool with a volatility-tuned curve — calm markets get a low, linear fee; stressed markets get a steeper, exponential one, so the pool itself resists getting drained during a spike.

Calm curve

Linear, ~120 bps. Used when the regime detector reads low volatility.

Stress curve

Exponential, up to 900 bps. Kicks in automatically when volatility jumps.

Fill verification

Every fill is checked against the logged decision; a bad fill halts the agent rather than getting absorbed silently.
